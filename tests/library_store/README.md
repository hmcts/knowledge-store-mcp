# Contract tests against the library

Moved from the repository README. Run the commands below from the repository root.

`tests/library_store/` holds two stores that knowledge-store-builder v0.19.1's own stages wrote, over a tiny invented estate (`example-org`: `alpha-lib`, `beta-app`, `delta-deploy`, `eta-portal`). `store/` has the query index; `no-index/` is the same inputs built without it. The `tests/test_library_*.py` tests call every tool against both and compare with values derived by hand from the inputs.

- **Regenerate inside the image** with `uv run python tests/library_store/generate.py --in-container`, then confirm the output reproduces with `uv run python tests/library_store/generate.py --check --in-container`. The host needs Docker (or Podman, with `CONTAINER_ENGINE=podman`) and network access. The first run builds the image from `tests/library_store/Dockerfile`. Every run builds the frozen environment and downloads the embedding model (about 90 MB) inside the container.
- **Why the image:** several tools besides the pinned packages write bytes into the stores. git dates every commit, and its `%cI` format reaches provenance, history and the manifest. gzip recompresses the graph. The interpreter's SQLite writes the index, and its zlib writes every `.gz` layer the library writes itself. On another machine these differ, and the stores differ with them. The image fixes all of them: its base is pinned by digest, git 2.55.0 is built from the checksummed release, gzip comes with the base, and uv installs its managed CPython 3.14.7. A store generated in the image is the same byte for byte on any machine that runs the image, arm64 or amd64. Run without `--in-container`, the generator still works but warns that its result is only that machine's.
- **The embedding model:** fastembed cannot be told which revision of the model to download. The pipeline records the revision it got and the sha256 of each model file in `knowledge/semantic/manifest.json`, which is committed. `--check` then fails, naming both revisions, if the hub's model moves.
- **Hand-written:** the inputs in `generate.py` (clone contents, commit messages, `config/`, agent-authored summaries and answers) and the tracker and GitHub answers in `tracker_responses.json` and `github_responses.json`. **Library output:** everything under `store/` and `no-index/`. Never edit those by hand.
- **Pins:** library v0.19.1 and graphify 0.9.93 in `generate.py`; every other package and the partitioner in `requirements.txt`. Each `requirements.txt` header also records the image its stores were made in: `# image:` is the base, by digest, and `# dockerfile:` is the sha256 of `Dockerfile`. `--check` prints both beside the running image's when they differ. Edit `Dockerfile` only together with a regeneration of every store; `test_library_generation` fails if a header names another image.
- **Seams only:** every IO edge is stood in for through the library's own seams: `fetch-tickets` through `opener=`, `sleep=` and `today=`, and `minimum-standard-settings` through `runner=` and a fixed `now=` clock.
- **Older stores:** `tests/library_store/frozen/` holds the same two stores built by older releases, v0.18.3 (manifest format 1.3, before `json-schema` and `minimum_standard`) and v0.19.0. Each has its own `requirements.txt`. `test_library_older_stores` checks that every tool still reads them. The pipeline skips each stage a release lacks, reading the release's own `cli.STAGES`. v0.19.0 has no `now=` seam, so for that release only, the stage module's `datetime` is rebound to the fixed clock. Rebuild one with `generate.py --release v0.18.3`, and only when its requirements are recompiled or the shared inputs in `generate.py` change. When a release is dropped from support, remove it from `RELEASES` and delete its directory under `frozen/` rather than rebuild it. `--check` covers them all.
- **Partial store:** `tests/library_store/partial/` holds the same pair built at v0.19.1 with the stages real stores often have not run skipped (`minimum-standard-settings`, `minimum-standard`, `topics`, `deepdive`, `deployments`), the git history kept local by a root `.gitignore`, and one repository, `zeta-archive`, retired from the estate after its history was exported. `generate.py` builds it alongside `store/` and `no-index/`, passing the skips to `pipeline.py --skip` explicitly; the pipeline still refuses a stage missing from the main pin. `test_library_partial` reads the library's absent-layer shapes through every affected tool.
- **Coverage:** `tests/library_store/COVERAGE.md` is the claim of what is covered, and `test_library_coverage` fails when a tool, argument or cited test is missing from it.
- **CI** runs the tests over the committed output, and the tests never run the generator. A separate workflow, `Contract stores` (`.github/workflows/contract-stores.yml`), runs `generate.py --check --in-container` on Linux x86_64. It runs on pull requests that touch `tests/library_store/**` and weekly, so drift is caught where it starts. It is not a required check, because it depends on the network.
