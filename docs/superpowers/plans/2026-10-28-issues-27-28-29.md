## Review Focus

1. A layer whose manifest path doesn't exist on disk. It must be reported as missing, not as a mismatch, and never crash `store_info` (Task 1).
2. A huge layer file. Digest it streamed, in chunks, never read whole (Task 1).
3. A store re-resolved mid-session while a cursor from the old store is still in use. The cursor must be refused, not silently applied to the new store (Task 2).
4. The served store's identity must never leak a host path (Task 2).
5. A container build that silently uses the host's tools: git, gzip or the Python build. The `--check` failure output must show the image digest (Task 3).

### Task 1: `store_info` flags layer digests that don't match the files (#29)

**Branch:** `feat/digest-check`

**Rulings (controller):**
- Check **single-file layers** only. The digest is the first 16 hex digits of the file's sha256, streamed in 1 MiB chunks. That is the library's `store_manifest._file_digest` at v0.19.1; cite it in a comment.
- Leave directory layers (`relationships`, `minimum_standard`, `history`) unchecked. A directory digest depends on which files a git clone receives (`_probe`), and the server can't reproduce that faithfully. Report them as `digest_unchecked: [names]` so the omission is visible.
- Output, in `store_info` only (no change to other tools): `digest_mismatch: [layer names]`, sorted, and `[]` when all match. A declared file that is missing from disk is not a mismatch. It goes in `digest_missing: [names]`.
- Never put a path or file contents in these fields. Layer names only.
- Compute once per loaded store, at the same point the store is opened or reloaded, so a reload recomputes. Don't hash on every call.

**Files:**
- `src/knowledgestore_mcp/store.py` (or a new small module `digests.py`, at the implementer's choice, reported).
- `src/knowledgestore_mcp/tools_graph.py` (`store_info`).
- `tests/test_library_digests.py`.
- README Troubleshooting.
- `tests/library_store/COVERAGE.md`.

**Steps:**
- [ ] Write the failing tests first.
  - **Store contract:** copy `tests/library_store/store` into a temp dir. Check that `store_info` reports `digest_mismatch == []`, `digest_missing == []`, and the three directory layers in `digest_unchecked`, in both index modes.
  - **Mismatch:** append one byte to a single-file layer, e.g. `knowledge/answers.json`, which is an extra layer only if the manifest digests extras (check the library). Otherwise use `knowledge/topics/briefs.json`. Check that `store_info` names exactly that layer.
  - **Missing:** delete a single-file layer and check it lands in `digest_missing`.
  - **Guard:** no field holds a `/`.

### Task 2: Say which copy is served, and switch to the registered clone (#28)

**Branch:** `feat/served-copy`

**Rulings (controller):**
- `store_info` gains:
  - `store_source`, one of `--store`, `KNOWLEDGE_STORE_PATH`, `--store-id` or `CLAUDE_PLUGIN_ROOT`, from `locate.Resolved.source`;
  - `served`: `{"store_id", "digest", "sources_as_of", "plugin_root": bool}`. `digest` is the manifest's top-level `digest`, or the sha256 of the manifest bytes when it has none. That is the same identity `store.Session.current` already uses.
  - No path.
- **Re-resolve.** When the store came from `CLAUDE_PLUGIN_ROOT`, and the locations file now holds an entry whose clone carries the same `store.id`, the next call switches to that clone. That call's answer carries a notice, e.g. `reloaded: now serving the registered clone`.
  - Never switch in the other direction.
  - Never switch away from `--store`, `KNOWLEDGE_STORE_PATH` or `--store-id`.
  - Check at most once per call, using the existing per-call check in `Session.current`. Read the locations file only when the source is the plugin root.
- **Cursors.** A cursor carries the store digest it was made for; check whether it already does. After a switch, an old cursor is refused with the existing foreign-cursor refusal.
- **KSB.** The library's `knowledge-store` skill pins server output, so the controller tells KSB about the new fields when the PR opens. The implementer doesn't message anyone.

**Files:**
- `src/knowledgestore_mcp/locate.py`.
- `src/knowledgestore_mcp/store.py` (`Session`).
- `src/knowledgestore_mcp/server.py` (passes the resolved source in).
- `src/knowledgestore_mcp/tools_graph.py`.
- Tests: extend `tests/test_locate.py` and `tests/test_server.py`, or add a new `tests/test_served_copy.py`.
- README: the "Troubleshooting" text that says how a skill detects a disagreement.

**Steps:**
- [ ] Write the failing tests first.
  1. `store_info` reports each of the 4 sources with the right `served` fields and no path.
  2. **The issue's case:** at start the locations file is empty and `CLAUDE_PLUGIN_ROOT` is a store. Later, an entry for a clone with the same `store.id` is written. The next call serves the clone, `served.digest` changes and `plugin_root` becomes false, and the notice is present.
  3. A locations entry for a *different* `store.id` doesn't switch.
  4. A `--store` start never switches.
  5. An old cursor after a switch is refused.

  Build the stores as temp copies of `tests/library_store/store` with a changed manifest digest, or use the fixture builder.
- [ ] Implement. Run the gates. Bite-check every test.
- [ ] README: how a skill compares `served.digest` with its own clone's manifest, and what the switch looks like.

### Task 3: The contract stores regenerate identically on any machine (#27)

**Branch:** `feat/reproducible-generator`

**Rulings (controller):**
- **Image.** A `tests/library_store/Dockerfile`, `FROM` a Debian-based image pinned by digest (`@sha256:…`). Prefer the uv-maintained `ghcr.io/astral-sh/uv:<ver>-bookworm`, or `python:3.14-slim-bookworm` with uv installed at a fixed version.
  - It installs, at fixed versions: git, gzip and the uv-managed CPython 3.14.x used by the frozen environments.
  - Record the image digest in each `requirements.txt` header, in place of the hand-written `# interpreter:` and `# git:` lines. Keep `# partitioner:`.
- **Running it.** `generate.py` gains `--in-container`, which builds the image if it's missing and runs itself inside it with the repo mounted. `--check` and the default mode both work that way.
  - Running outside the container still works, but prints a warning that the result is only reproducible in the image.
  - `--check` prints the recorded image digest and the running one when they differ.
- **Model.** Pin the fastembed model revision if fastembed supports it. If it doesn't, record the model's file hash in `semantic/manifest.json` (which the library already writes) and have `--check` compare it. Report which.
- **Regenerate.** Rebuild every store (main, no-index, partial, frozen v0.18.3 and v0.19.0) once, inside the image, and commit the result.
  - Literals derived from the inputs shouldn't move. If one does, the inputs-to-bytes chain depended on the host. Name each moved literal and why.
- **CI.** Add `.github/workflows/contract-stores.yml`. It is not a required check. It runs `generate.py --check --in-container` on PRs touching `tests/library_store/**` or that workflow, and weekly on a schedule. Actions are pinned to fixed versions.
- **Prove it.** Run `--check --in-container` on this Mac, which is arm64. The CI run on Linux x86_64 is the second platform. If amd64 and arm64 bytes differ (onnxruntime numerics in `semantic` are the likely cause), stop and report the files. Don't hide the difference.

**Files:**

- `generate.py`, `pipeline.py` (only if paths need to be container-aware), the `requirements.txt` headers, and the regenerated stores.
- `.github/workflows/contract-stores.yml`.
- `tests/library_store/README.md`.
- `.sonarcloud.properties`, if needed.
