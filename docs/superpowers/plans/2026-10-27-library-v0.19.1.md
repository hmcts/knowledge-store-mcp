# Library v0.19.1 Pin Move Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The library contract stores and the synthetic minimum-standard fixture are made by knowledge-store-builder v0.19.1, and the tests that v0.19.0's bugs kept silent now assert.

**Architecture:** The same generator (`tests/library_store/generate.py` + `pipeline.py`), pinned to v0.19.1. The clock rebinding gives way to the library's `now=` seam. The pin moves, both stores are regenerated, and every moved literal is re-derived by hand from the inputs. `provided_by` gets its first assertion. The synthetic fixture's minimum-standard records are re-transcribed from the v0.19.1 writer.

**Tech Stack:** as before. Python 3.14 (the generator's frozen environment, and the server after Task 3) stdlib `unittest`, `uv`, knowledge-store-builder v0.19.1 (tag on `a97b281`), `graphifyy[terraform,sql]==0.9.93`.

**Spec:** `docs/superpowers/specs/2026-10-23-library-contract-tests-design.md`. Its Anti-goals still bind every task.

## Global Constraints

- Library `git+https://github.com/hmcts/knowledge-store-builder@v0.19.1`. graphify stays at `graphifyy[terraform,sql]==0.9.93`. Recompile `tests/library_store/requirements.txt` with the same command its header records, and never edit a package line by hand. Keep the `# partitioner:`, `# interpreter:` and `# git:` header lines true for the machine that regenerates.
- The seam, as stated by the library owner: `build_minimum_standard_settings.main(runner=run_gh, now: Callable[[], datetime] = lambda: datetime.now(timezone.utc)) -> int`. Pass `now=lambda: datetime(2026, 10, 20, tzinfo=timezone.utc)`.
- v0.19.1 changes that reach layers the server reads. There is no format bump; only values move.
  - **#510:** `provided_by` goes from the package node to the lowest-id node whose `source_file` is the provider's `package.json` (`reps`), or else to its lowest non-JSON code node (`_code_anchor`), or else there is no edge. It never targets a `.json` or json-schema node. `USES_MODULE` edges now start from `_code_anchor` too.
  - **#508:** a file with a non-json-schema.org `$schema` and no `properties`/`definitions`/`$defs` is no longer claimed.
  - **#507:** `workspace:` and in-clone `link:`/`file:` references resolve to the repository itself.
  - **#511:** a `.pem`/`.key` file with no BEGIN boundary stays `key-file`; only `.crt`/`.cer` with no boundary are dropped. A name containing `truststore` or `cacerts` makes `no_secrets` `not_determinable`, so never use such a name.
  - **#509:** content-set entries are path-normalised and deduplicated.
- All the existing rules hold:
  - invented names only, because the repo is PUBLIC;
  - expected values are derived by hand and never read back from the store; shas come only from `inputs.json`;
  - never assert a community number;
  - every test opens its docstring with `Catches:` and is bite-checked;
  - `fixture-not-a-secret` is the only secret-looking value;
  - the gates are chained with `&&`, never piped: `uv run ruff check . && uv run ruff format --check . && uv run pyright && uv run python -m unittest discover -s tests`;
  - stage explicit paths only;
  - commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`;
  - a hook blocks `rm -r`, so use `find … -delete`.
